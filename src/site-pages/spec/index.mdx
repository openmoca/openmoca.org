MOCA (Modular Ontology, Content & Attestation) is defined by seven documents, a
set of JSON Schemas, and a conformance corpus that every Reader must pass. They
are versioned together: these pages describe **0.7.0**, before 1.0
([versioning](/spec/versioning/)). The source of every page is the
[moca-spec repository](https://github.com/openmoca/moca-spec).

## The specifications

| Document | What it defines | Status |
| --- | --- | --- |
| [Package specification](/spec/package/) | The package: manifest, credits, dates, the creator's terms, OKF content, evidence, machine-made marks, locales, trust fields, structure, members, relations, the digest, profiles and capabilities | 0.7.0 |
| [Reader contract](/spec/reader-contract/) | What every Reader must conclude: reading, verifying, citation records, the retrieval policy, search, structure, diagnostics and the creator's terms | 0.7.0 |
| [Reader interface](/spec/reader-interface/) | The operations and objects every Reader offers, named for each language | 0.7.0 |
| [Attestations](/spec/attestations/) | Package, review and issued-copy attestations, signing modes, trust roots and verification outcomes | 0.7.0 |
| [Encrypted packages](/spec/encrypted-package/) | A signed package in an age envelope: the readable outline and its check, key providers, limits, and what encryption does not do | 0.7.0 |
| [Sidecar index](/spec/sidecar-index/) | Portable lexical and semantic indexes beside a package, bound to its digest | 0.7.0 |
| [Citations over AG-UI](/spec/ag-ui-citations/) | One AG-UI event that carries an answer's citation records to a user interface | 0.7.0 |

Extensions are [profiles](/spec/profiles/); the [ontology profile](/spec/profiles/ontology/)
is a draft. The [app types](/spec/app-types/) a package's `apps` hint can name, and suggested [node types](/spec/node-types/), are listed here too.

## Files and media types

| File | Extension | Media type |
| --- | --- | --- |
| A package | `.moca` | `application/vnd.openmoca.package+zip` |
| An encrypted package's envelope | `.mocae` | `application/vnd.openmoca.envelope+zip` |
| A sidecar search index | `.mocai` | `application/vnd.openmoca.index+zip` |

Each is a Zip file, and a Reader recognises each by its contents, not its name
([package specification §12.1](/spec/package/#121-media-types)).

Each schema is published at its `$id`, so validators can fetch it:

| Schema | For |

| [`node.schema.json`](/schemas/v1/node.schema.json) | A page's frontmatter |
| [`terms.schema.json`](/schemas/v1/terms.schema.json) | The creator's terms, `terms` in `moca.json` |
| [`structure.schema.json`](/schemas/v1/structure.schema.json) | `structure.json`, the view of `structure.ttl` |
| [`citation-record.schema.json`](/schemas/v1/citation-record.schema.json) | A citation record |

## Conformance

The [conformance corpus](/spec/conformance/) is @@release.suite@@: each case
is a package, options and the conclusions every Reader must reach. Each
release attaches the corpus as `moca-conformance-<version>.tar.gz`, so an
implementation can pin it.

Software that passes the suite for what it is, for a named version, may say
it is **OpenMOCA Conformant**. Listings are coming soon
([OpenMOCA Conformant](/conformant/)).
