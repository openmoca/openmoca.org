**For software.** Anyone can build software that reads or makes MOCA packages
(the files OpenMOCA keeps a work in, with its credits, sources and wishes),
without asking. OpenMOCA Conformant is a public listing of the software that
passes the public OpenMOCA tests, so people choosing software can see what it
has shown. It is part of the [OpenMOCA Directory](/directory/).

## What it means

The standard is only useful if all software reads a package the same way.
Software may say it is OpenMOCA Conformant when it passes the public tests for
what it does: **reads** packages, **makes** them, or **checks** them, and other
kinds as tests are written for them. The claim names the kind of software and
the version of the standard
([the exact wording](https://github.com/openmoca/moca-spec/blob/main/TRADEMARKS.md)).
Each listing names the software, its version, the specification version and
the tests it passed.

## The three standings

| Standing | Means |
| --- | --- |
| **Official** | The project's own software, such as its Readers and tools |
| **Verified** | The project has run the tests again on that version itself |
| **Self-tested** | The maker ran the public tests and published a signed result |

## Software that is listed

Each entry links to its public test run on GitHub. The signed record of each
result, and the tool that makes it, come after 0.7.0.

## How to get listed

Run the tests yourself; they are [public](/spec/conformance/). There is no fee
and no application form. Publish the signed result, then ask for it to be
listed at [hello@openmoca.org](mailto:hello@openmoca.org). A result covers one
version: if a later version of the software fails the tests, the claim is
updated or removed. A listing that fails when the tests are run again is
removed.

## Tests for software that makes or checks packages come later

Today's tests are for software that reads OpenMOCA. Software that makes or
checks packages is listed once tests for it exist.
